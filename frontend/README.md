# PITCH TWIN 프런트엔드

첨부된 랜딩·결과 화면 설계를 바탕으로 만든 프런트엔드입니다. 실행 시 별도 Node
프로세스는 필요하지 않으며 FastAPI가 `/app/`에서 정적 화면과 빌드된 3D 뷰어를 제공합니다.

## 실행

원본 Statcast 데이터와 프로젝트 의존성을 준비한 뒤 루트에서 처음 실행할 때는
전처리를 포함하여 서버를 시작합니다.

```bash
python main.py --k 6
```

브라우저에서 `http://127.0.0.1:8000`을 열면 `/app/`으로 이동합니다. 프런트엔드와 API를
같은 서버에서 제공하므로 별도의 CORS 설정은 필요하지 않습니다.

`--skip-preprocess`는 `data/processed/pitcher_clustered.json`과
`pitcher_profile.csv` 등 필요한 산출물이 이미 준비된 경우에만 사용합니다.
화면만 확인할 때는 `python3 -m http.server 8001 --bind 127.0.0.1 --directory frontend`로
정적 파일을 제공할 수 있습니다. 이때 API 요청은 `http://127.0.0.1:8000`의 백엔드로
전달됩니다. 정적 서버만 실행하면 화면은 열리지만 투수 검색은 할 수 없습니다.
다른 API 주소를 사용할 때는 HTML을 로드하기 전에 `window.PITCH_TWIN_API`로 지정할 수 있습니다.

## 화면 흐름

1. 투수 이름 또는 MLB ID, 시즌, 유사 순위를 입력합니다.
2. `GET /pitchers`에서 이름 자동완성을 받고 `GET /{player_id}/{year}?rank=N`으로 비교 프로필을 표시합니다.
3. 프로필을 먼저 보여 준 뒤 `GET /trajectory/{player_id}/{year}`와 `GET /cluster-map/{player_id}/{year}?rank=N`에서 3D 궤적 및 전체 패스트볼 GMM 지도를 각각 불러옵니다. 생성형 AI 키가 없으면 `GET /{player_id}/{year}/llm?rank=N`은 AI가 아닌 수치 기반 설명을 제공합니다.
4. 이전·다음 순위 버튼은 같은 투수와 시즌으로 `rank`만 바꿔 다시 조회합니다.

기존 `src/visualization/pitch_3d` React 뷰어를 번들링한 `three-viewer.js`가
두 투수의 3D 궤적을 겹쳐 표시합니다. 구종별 시즌 전체 최대 12개 투구를
표본 추출해 공개 Statcast 운동 계수로 복원하며 원본 영상 프레임은 아닙니다.
기본 화면은 시즌 전체 `plate_x`·`plate_z`의 0.25ft 최빈 구간 중심에 가장 가까운
실제 투구를 각 투수·구종당 1개만 보여 줍니다. 이 투구는 표본에도 포함됩니다.
먼저 두 투수 또는 한 투수를 선택하고, 각 투수의 구종을 독립적으로
필터링할 수 있습니다. 구종 옆의 구사율과 평균 구속은 정규시즌 전체 투구 기준이며,
10% 미만 구종은 비교 화면에서 제외됩니다(정확히 10%는 포함). 표본 개수와 다릅니다. `전체 표본 보기`로 나머지 궤적을 펼칠 수 있습니다. 궤적 색은
구종별로, 실선·점선은 투수별로 구분합니다. 끝점은 Statcast의 `plate_x`·`plate_z`
좌표이며 화면의 고정 존 테두리는 타자별 실제 판정 존이 아닙니다.

GMM 지도는 기존 3변수 모델의 투구별 군집 결과를 IVB–HB 2차원 점으로 투영합니다.
원본 2021–2025년 패스트볼 중 군집별 실제 투구 최대 180개를 점으로 표시하며,
타원이나 영역 경계는 그리지 않습니다. A·B는
각 투수-시즌 FF·SI·FC 전체 평균 IVB·HB 위치를 나타내는 점 하나씩이며,
점 라벨에는 투수 이름만 표시하고 동일 표본의 평균 팔 각도는 상세 정보에
표시합니다. 최빈 군집은 시즌 투구별 3변수 GMM 결과로 별도 표기합니다.
따라서 평균점 주변의 색 점과 최빈 군집 번호가 다를 수 있습니다.
A는 흰색 채움, B는 어두운 채움과 흰 테두리의 중립색 마커로
군집 색과 구분합니다. 첫 조회에서는 전체 패스트볼을 분류해
`data/processed/cluster_map_k{K}_v2.json`을 만들 수 있어
시간이 걸리지만, 다음 조회부터 이 캐시를 재사용합니다.
뷰어 소스를 수정한 뒤에는 해당 디렉터리에서 `npm ci && npm run build:comparison`을
실행해 프런트엔드 번들을 다시 만드세요.
